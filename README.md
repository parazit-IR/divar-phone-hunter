# شکارچی گوشی دیوار (Divar Phone Hunter)

ایجنت هوش مصنوعی با Spring Boot که آگهی‌های جدید **آیفون ۱۳ تا ۱۵** و **سامسونگ سری S و A** را در دیوار زیر نظر می‌گیرد،
هر آگهی را با **میانه‌ی قیمت همان مدل + همان حافظه + همان وضعیت** در شهر شما مقایسه می‌کند
و اگر «شکار» بود، به **ربات تلگرام** شما خبر می‌دهد.

---

## معماری: Agent = Model + Harness

```
                ┌──────────────────── Harness (Spring Boot) ────────────────────┐
                │                                                                │
  هر ۵ دقیقه ──▶│  Tool: DivarClient ──▶ Extract (Regex) ──▶ Context: SQLite      │
                │        (آگهی‌های جدید)    (مدل/حافظه/وضعیت)   (تاریخچه‌ی قیمت‌ها)  │
                │                                    │                           │
                │                                    ▼                           │
                │                 Observe: میانه / P25 / P75 هر گروه              │
                │                                    │                           │
                │                                    ▼                           │
                │   Decide: DealEvaluator ──▶ RiskRules ──▶ Model (LLM, اختیاری)  │
                │                                    │                           │
                │                                    ▼                           │
                │                       Act: TelegramNotifier                    │
                └────────────────────────────────────────────────────────────────┘
```

| بخش در عکس‌ها | کلاس در پروژه |
|---|---|
| Agent Loop | `agent/HunterAgent` |
| Tools | `divar/DivarClient`، `notify/TelegramNotifier` |
| Context / حافظه | `store/ListingRepository` + فایل `data/hunter.db` |
| Model | `llm/HttpLlmAdvisor` (اختیاری) |
| Permissions | فقط خواندن و خبر دادن؛ به فروشنده پیام نمی‌دهد و چیزی نمی‌خرد |
| Errors / Timeout | Retry و Backoff در `DivarClient` و فاصله‌ی بین درخواست‌ها |

## منطق «شکار»

یک آگهی وقتی به تلگرام فرستاده می‌شود که **همه‌ی** این شرط‌ها را داشته باشد:

1. مدل، حافظه و وضعیتش (نو، در حد نو یا کارکرده) با اطمینان تشخیص داده شده باشد.
2. گروهش در ۱۰ روز اخیر دست‌کم **۸ آگهی** داشته باشد (`min-samples`).
3. قیمتش دست‌کم **۱۲٪ زیر میانه** باشد، ولی بیشتر از **۴۰٪** پایین‌تر نباشد. قیمت خیلی پایین معمولاً فیک یا طعمه است.
4. **سود تخمینی** = صدک ۷۵ − قیمت آگهی − هزینه‌ی جانبی، دست‌کم ۲ میلیون تومان باشد.
5. در متن آگهی «فقط معاوضه»، «قطعه‌ای»، «رجیستر نشده یا نات‌اکتیو»، «کپی» یا «فقط جعبه» نیامده باشد.
6. اگر مدل زبانی فعال باشد، آن هم آگهی را رد نکرده باشد.

هشدارهای نرم (باتری زیر ۸۵٪، اشاره به آیکلود، قطعه‌ی تعویضی، قسطی بودن) مانع ارسال نمی‌شوند و فقط زیر پیام نمایش داده می‌شوند.
هر آگهی فقط یک بار اعلام می‌شود، مگر اینکه فروشنده دوباره قیمتش را پایین بیاورد.

> اجرای اول (bootstrap) فقط داده جمع می‌کند تا میانه ساخته شود و پیامی نمی‌فرستد. از اجرای دوم به بعد شکارها می‌رسند.

## نصب و اجرا

### پیش‌نیازها
- **Java 21**
- **Maven 3.9 به بالا**، یا IntelliJ IDEA که Maven را خودش دارد

### اجرا
```bash
mvn spring-boot:run
```
یا در IntelliJ: `Open` → پوشه‌ی پروژه → فایل `PhoneHunterApplication` → دکمه‌ی Run.

ساخت فایل jar:
```bash
mvn clean package
java -jar target/divar-phone-hunter-0.1.0.jar
```

### ساخت ربات تلگرام
1. در تلگرام به `@BotFather` پیام بدهید، دستور `/newbot` را بزنید و **توکن** را بگیرید.
2. به ربات خودتان یک پیام بدهید، مثلاً `سلام`.
3. آدرس `https://api.telegram.org/bot<TOKEN>/getUpdates` را در مرورگر باز کنید. عدد `chat.id` همان **chat-id** شماست.
4. در `application.properties` بنویسید:
```properties
hunter.telegram.enabled=true
hunter.telegram.bot-token=123456:ABC...
hunter.telegram.chat-id=123456789
```

### ⚠️ نکته‌ی مهم شبکه (ایران)
- **دیوار** معمولاً فقط با **IP ایران** جواب می‌دهد، پس اتصالش مستقیم باشد.
- **تلگرام** فیلتر است، پس پیام‌ها را از طریق پراکسی محلی VPN بفرستید:
```properties
# مثال v2rayN: پراکسی HTTP روی پورت 10809
hunter.telegram.proxy-host=127.0.0.1
hunter.telegram.proxy-port=10809
```
VPN را روی حالت **سراسری (System Proxy / TUN)** نگذارید، وگرنه دیوار هم از مسیر VPN می‌رود و ممکن است بلاک شود.
برنامه برای هر سرویس پراکسی جدا دارد، پس می‌توانید VPN را فقط برای تلگرام و LLM استفاده کنید.

## تنظیمات مهم (`src/main/resources/application.properties`)

| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `hunter.city.id` | `1` | تهران=1، کرج=2، مشهد=3، اصفهان=4، تبریز=5، شیراز=6 |
| `hunter.city.name` | `Tehran` | فقط برای نمایش در پیام |
| `hunter.queries` | آیفون و سامسونگ | عبارت‌های جستجو. `iphone` و `samsung` خودکار فارسی می‌شوند. |
| `hunter.poll.interval-ms` | `300000` | فاصله‌ی دو اجرا (۵ دقیقه) |
| `hunter.deal.min-discount-percent` | `12` | حداقل درصد زیر میانه |
| `hunter.deal.min-profit-toman` | `2000000` | حداقل سود |
| `hunter.deal.extra-cost-toman` | `500000` | هزینه‌ی شما در هر معامله (رفت‌وآمد، تست، نردبان) |
| `hunter.stats.window-days` | `10` | میانه از آگهی‌های چند روز اخیر حساب شود |

فایل `.properties` در Spring با ISO-8859-1 خوانده می‌شود، پس متن فارسی را مستقیم در آن ننویسید.
برای همین جستجوها را به‌صورت `iphone 13` یا `samsung S24` بنویسید. برنامه خودش آن‌ها را به «آیفون ۱۳» و «سامسونگ S24» تبدیل می‌کند.

### عوض کردن شهر
```properties
hunter.city.id=3
hunter.city.name=Mashhad
```
اگر کد شهری را نمی‌دانید، در مرورگر سایت divar.ir را باز کنید، کلید F12 را بزنید و به تب Network بروید.
شهر را عوض کنید و در درخواست `search` مقدار `city_ids` را ببینید.

یادتان باشد میانه‌ها برای هر شهر جدا ساخته می‌شوند، پس بعد از عوض کردن شهر اجرای اول دوباره حالت bootstrap دارد.

## مدل زبانی (اختیاری)

بدون مدل زبانی هم سیستم کامل کار می‌کند و فقط از قوانین Regex استفاده می‌کند.
اگر مدل زبانی فعال باشد، **فقط** آگهی‌هایی که از همه‌ی قوانین رد شده‌اند (روزانه چند تا) برای بررسی متن به مدل فرستاده می‌شوند، پس هزینه‌اش خیلی کم است.

**Claude API (کلید از console.anthropic.com):**
```properties
hunter.llm.provider=anthropic
hunter.llm.api-key=sk-ant-...
hunter.llm.model=claude-haiku-5-5
hunter.llm.proxy-host=127.0.0.1
hunter.llm.proxy-port=10809
```

**مدل محلی رایگان با Ollama:**
```properties
hunter.llm.provider=openai
hunter.llm.base-url=http://localhost:11434/v1
hunter.llm.model=qwen2.5:7b
```

> اشتراک Claude Pro شامل API نیست. API یک حساب جدا در Claude Console دارد و جدا پرداخت می‌شود.

## عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| `Divar HTTP 400` | مقدار `hunter.divar.sort` را خالی کنید. اگر درست نشد، احتمالاً ساختار API دیوار عوض شده (پایین را ببینید). |
| `Divar HTTP 403` یا `429` | VPN را برای دیوار خاموش کنید و `request-delay-ms` را بیشتر کنید. |
| `fetched=0` در لاگ | API دیوار تغییر کرده است. |
| پیام تلگرام نمی‌رسد | پراکسی تلگرام را چک کنید. در لاگ دنبال `Telegram send failed` بگردید. |
| `outcomes={TOO_FEW_SAMPLES=...}` | داده هنوز کم است. چند ساعت صبر کنید یا `min-samples` را کم کنید. |

**API دیوار رسمی نیست.** اگر دیوار ساختار پاسخ را عوض کند، فقط دو فایل `DivarClient` و `DivarResponseParser` باید اصلاح شوند.
برای پیدا کردن ساختار جدید، در تب Network مرورگر پاسخ درخواست `search` را ذخیره کنید و جای فایل `src/test/resources/divar-search-sample.json` بگذارید.
